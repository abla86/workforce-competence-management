# Vaktklar / Workforce & Competence Management — teknisk audit 2026-08-20

## Status

**Prototype: under verifikasjon.** PR #18 er gjort klar for review. Endringene er lagt på `audit-hardening-2026-08`.

## Kontroller utført

- Backend target: .NET 10.
- Frontend: npm CI + lint + production build.
- Docker Compose-konfigurasjon valideres i CI.
- Full stack smoke test starter SQL Server, API og frontend.
- API-helse kontrolleres mot eksisterende databaseavhengige `/health`-endpoint.
- API-containeren kjører som ikke-root bruker (`APP_UID`).
- Frontend har sikkerhetsheadere og reverse-proxy for API.
- Auth har JWT-validering, HttpOnly-cookie, rate limiting, konto-lockout og rollebasert autorisasjon.
- Eksport/import/share-endepunkter er beskyttet av autentisering.
- Backend unit-testene inkluderer coverage-logikk og PlanningAdvisor-regler.
- CI har separat backend-, frontend- og Docker-jobb.
- CodeQL og Dependabot er konfigurert.

## Feil funnet og korrigert i denne runden

### 1. PlanningAdvisor-test

Den første full-stack CI-kjøringen viste 10 beståtte og 1 feilet test i `ValidCandidateIsRankedEligible`. Test-fixturet manglet eksplisitt `PositionPercent`, mens domenelogikken korrekt avviser kandidater med stillingsprosent <= 0.

Test-fixturet er kontrollert på nytt og bruker nå `PositionPercent = 100m`. Dette er en testkorrigering, ikke en svekkelse av domeneregelen.

### 2. Docker API healthcheck

Compose smoke-testen stoppet tidligere ved API health. Runtime-containeren hadde ikke et eksplisitt HTTP-klientverktøy for Compose healthcheck. `curl` er nå installert i API-runtime-image, og Compose bruker det eksisterende databaseavhengige `/health`-endpointet.

### 3. Frontend oppstart

Frontend venter nå på at API-tjenesten er `service_healthy`, ikke bare at containeren er startet. Dette reduserer race conditions ved lokal/demo-oppstart.

### 4. SQL Server healthcheck

SQL Server healthcheck er gjort eksplisitt med `CMD-SHELL`, exit-status og startperiode.

## Duplisering / konsistens

Det er ikke lagt inn en ny parallell health-mekanisme når eksisterende `/health` allerede dekker databaseberedskap. Compose er koblet til denne eksisterende mekanismen i stedet for å introdusere et redundant endpoint.

Det samme gjelder OpenAPI: prosjektet bruker .NET 10 sin eksisterende `AddOpenApi()`/`MapOpenApi()`-mekanisme. En ekstra Swagger-stack er derfor ikke lagt oppå denne uten behov.

## Gjenværende begrensninger

Dette er fortsatt en prototype og skal ikke beskrives som produksjonsklar uten videre arbeid.

1. EF Core migration-historikk er ikke etablert som produksjonsmigreringsløp.
2. Frontend har ikke full Playwright/E2E-suite ennå.
3. Integration testing mellom API og database bør utvides før produksjonsbruk.
4. Coverage-måling og badge er ikke etablert som kvalitetsgate.
5. Observability/metrics er fortsatt begrenset sammenlignet med et produksjonssystem.
6. Rollemodellen kan raffineres videre dersom systemet skal ha separate employee/auditor-tilganger.
7. Produksjonsdeploy, HTTPS, secret management og backup/restore må valideres i målmiljøet.

## Kvalitetsregel videre

En endring skal ikke regnes som ferdig før:

1. prosjektet bygger,
2. relevante tester passerer,
3. Docker Compose starter hele stacken,
4. healthcheck passerer,
5. autentisering fungerer,
6. minst én beskyttet API-flyt er verifisert,
7. frontend bygger og svarer,
8. dokumentasjonen beskriver faktiske begrensninger.
