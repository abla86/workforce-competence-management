# UX Research Plan

The product should not assume that the current workflow is acceptable. Existing staffing systems are often experienced as difficult when they provide limited influence, poor transparency, excessive manual work, weak flexibility, or insufficient support for workload and fairness decisions.

## Questions to validate with users

1. What task takes the most time today?
2. Where do users make manual calculations or keep parallel notes?
3. Which warnings are currently discovered too late?
4. What information is needed before accepting a replacement candidate?
5. Which rules must never be overridden automatically?
6. Which preferences should employees be able to control themselves?
7. Which parts of the schedule are hardest to change after publication?
8. What makes a staffing recommendation trustworthy or untrustworthy?
9. Which screens are used daily versus occasionally?
10. What terminology matches the users' real workflow?

## Usability acceptance criteria

For core tasks, evaluate:
- completion time
- number of interactions
- error rate
- need for external notes/calculations
- user confidence in the result
- perceived transparency

Core tasks:
- identify an uncovered shift
- understand why it is uncovered
- find a qualified replacement
- verify the replacement
- register absence
- understand the impact of absence
- review weekly staffing status
- correct a competence record
- create a work-task requirement

## Design principle

Research findings are hypotheses for this product, not proof of what local users want. Local users must be involved before claiming that a workflow is optimal.
